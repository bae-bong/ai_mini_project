# 필수 프론트엔드 페이지

Vue 3 런타임을 프로젝트에 포함한 정적 앱이다. 별도 Node 서버·npm 설치·프론트 이미지 빌드 없이 Nginx가 제공한다.

| 주소 | 기능 |
|---|---|
| `/signup` | 아이디·비밀번호 확인·직원 수·기업 유형 복수 선택 |
| `/login` | 로그인·오류·가입 완료·로그인 만료 안내 |
| `/chat` | 경영지원/사업공고 선택, 질문, 답변·출처·기업 정보·전문가 확인 안내 |
| `/documents` | 자료 준비 상태, 경영지원 PDF 등록·검증·결과·관리 자료 제한 안내 |

`/`는 `/chat`으로 이동하고, 로그인이 없으면 `/login`으로 이동한다. 보호는 화면 이동뿐 아니라 기존 API의 JWT 검증으로 수행한다. 토큰을 localStorage에 저장하지 않는다. 기존 개발 콘솔과 인증 서버의 원래 경로는 유지한다.

## API 연결

- 회원가입·로그인·로그아웃: `/api/auth/signup`, `/api/auth/login`, `/api/auth/logout`
- 사용자·기업 정보: `/api/rag/me`
- 자료 상태: `/api/rag/health`
- 상담: `/api/rag/rag-query`
- 음성 질문 인식: `/api/voice/stt/`
- 답변 듣기: `/api/voice/tts/`
- 경영지원 자료: `/api/rag/upload-paper`

화면 표시 이름만 경영지원/사업공고로 바꾸고 요청의 `source` 값은 기존 `pdf`/`web`을 유지한다. 자료가 없는 분야는 상담 제출을 비활성화한다. 사업공고 등록·자료 목록·삭제·대화 기록·기업 정보 수정은 API가 준비되지 않아 추가하지 않았다. 파이프라인 관리 자료 업로드의 409 응답은 담당자에게 변경을 요청하는 안내로 표시한다. 현재 업로드 권한은 기존 API와 동일한 로그인 사용자 기준이며 관리자 권한을 새로 가정하지 않는다.

`/chat`의 음성 입력은 최대 60초 녹음 후 질문란에 문장을 넣는다. 사용자가 확인·수정하고 제출하면 기존 RAG 검색을 수행한다. 답변 듣기는 요청할 때 생성하며 실패해도 텍스트와 출처는 유지한다. [음성 검색 설계·실행·검증](../docs/VOICE_SEARCH.md)을 참고한다.

## EC2에 반영

커밋·push 후 EC2에서 최신 코드를 받는다. 기존 DB와 RAG가 동작 중인 경우 다음으로 Nginx의 새 정적 파일 마운트·경로와 인증 서버의 로그인 이동 경로를 적용한다.

```sh
git pull --ff-only origin feat-devops
sudo docker compose up -d --no-deps --no-build --force-recreate nginx auth
```

프론트 파일만 바꾸는 작업은 EC2에서 이미지를 다시 빌드할 필요가 없다. **음성 검색을 처음 추가하는 배포는 `voice` 이미지 빌드·실행과 Nginx 반영이 함께 필요**하므로 [음성 검색 배포 안내](../docs/VOICE_SEARCH.md#실행)를 따른다. HTTPS 배포는 `compose.public.yaml` 옵션을 유지한다. 전체 첫 실행은 루트 배포 문서를 따른다. SSH 터널의 기존 주소에서 `/signup`, `/login`, `/chat`, `/documents`에 접속한다.

## 검증

```sh
node --check frontend/assets/app.js
python3 deploy/smoke_test.py
```

브라우저 점검: 비밀번호 불일치 → 가입 → 기업 유형 두 개 선택 → 로그인 → 기업 정보 확인 → 미적재 분야 안내 → 답변·출처·전문가 안내 → 자료 관리 → 파일 형식 오류 → 관리 자료의 업로드 제한 → 로그아웃 → 보호 페이지 재접속. 답변·업로드 응답을 UI에서 시험할 때는 테스트 대역을 사용해 AI API 비용이 발생하지 않도록 한다. 모바일 너비에서도 가로 넘침과 키보드 탭 이동을 확인한다.
